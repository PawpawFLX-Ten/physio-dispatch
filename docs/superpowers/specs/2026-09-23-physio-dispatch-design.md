# 治疗室派工小程序设计

> **历史设想（2026-09-23）**：下文是早期微信小程序/云端口令方向的产品设想，保留作背景，**不是现行实现**。  
> **现行产品**：局域网 Node 服务 + React 客户端（可选 three 人体）。有效规则与日常操作见仓库根目录 [README.md](../../../README.md) 与 [docs/治疗室使用说明.md](../../治疗室使用说明.md)。

日期：2026-09-23

之之是主治医师。这个微信小程序给治疗室用：把一次康复按摩、松解和器械训练，按顺序派给实习或助手。人体用来点选要做的肌肉和节点。病症记住这串安排，下次不必重新点。

## 谁在用

- 之之排今天的病人，也可以口头说顺序。
- 实习和助手看同一张今日单，接自己的项，也可以把听到的顺序记到单上。
- 打开小程序的人看到今天全部病人的姓名、病症和各项派工。

第一版不做账号注册，也不按身份限制谁能改。

## 进入

治疗室共用一个口令。第一台打开的微信设定口令，并写下第一个名字。其余微信输入这个口令，再从治疗室名单里点一次「我是谁」。之后这台微信直接打开今日单，名字绑在这台微信上，用来默认派发和记录是谁点的完成。

口令存在云端。换口令之后，各台微信要重新输入。名单里的名字任何人都可以添加。今日单按治疗室所在地的日历日切换，过了零点就是新的一天。

## 今日单

打开就是今天的病人列表。每行是病人姓名、今天选中的病症、已完成几项。所有人看到的是同一张单。

底部有「加入病人」。老病人点名字进入。只有一条病症时，手法、方向、剂量和顺序直接出现，不用打开人体。有多条病症时，点一下今天要做的那几条，按点选先后接成一条顺序，之后仍可拖动。

顶部「全部派给某人」把这个病人今天的各项一次派给同一个人。某一项不同，再单独改。做完点该项的完成。再点一次改回未完成。完成只记在今天。

## 新病人和新病症

新建时写下姓名和第一条病症名称。然后在人体上按治疗先后点肌肉或节点。点一下就成为下一项，序号同时出现在模型上。手法、方向、剂量和派给谁沿用上一处。第一处默认：按摩、沿肌纤维、时长 8 分钟、派给当前这个人。点错左滑去掉。要改某一项，再点开那一行。

离开这一页时，这串自动写入该病症。

进入人体后，第一次点选标的是要治的地方（例如膝盖），用单独的颜色，本身不是下手任务。之后点的都是下手项，例如腘绳肌、比目鱼肌、足底、腰。要改要治的地方，点已标出的那个位置再重选。

## 顺序

一个病人今天只有一条顺序，不管各项派给谁。点选的先后就是顺序。要改就拖清单右侧的手柄，人体上的数字一起变。

被派的人可以自己记。病症里已有的项，听完口头交代后拖成所说的先后。还没有的项，由这个人按口头顺序在人体上点上。之之和助手改的是同一条顺序。

## 病症

病症记在病人身上。一个病人可以有多条，例如右膝疼痛、腰紧。每条保存：要治的地方，以及下手项的肌肉或节点、手法、方向、剂量、顺序。

派给谁和完成只属于今天的快照，不写回病症。改了部位、手法、方向、剂量或顺序，离开时问一句是否更新病症，默认不更新。

把一条病症复制到另一个病人，成为对方的一条病症。复制后派给谁重新填。这是跨病人复用的方式。

## 触屏

竖屏、一只手。主要动作用点选，放在拇指够得到的位置。

- 今日单每行可以整行点中。
- 人体单指转动。点一块肌肉或一个节点即选中。
- 改某一项时，从底部升起操作卡：手法三选一（按摩、松解、器械），方向四个词（沿肌纤维、逆肌纤维、由近到远、由远到近），剂量用加减，派给谁用名单点选。
- 按摩和松解的剂量是时长，按分钟加减。器械的剂量是组数和次数。
- 排序用足够粗的拖动手柄。去掉用左滑。
- 完成用该项上的大按钮。

## 人体

小程序原生页面。人体用微信 xr-frame 加载 `.glb`。网格从 BodyParts3D 裁出治疗室常用肌肉，例如大腿后侧、小腿、足底相关肌肉、腰部肌肉。腘绳肌若在数据里是股二头肌、半腱肌、半膜肌，界面对外仍是一个可点的名字「腘绳肌」。

再分发这些网格时保留 BodyParts3D 的署名。程序若使用 `human-atlas` 的代码，代码部分遵守 MIT。

筋膜和穴位不做现成网格层。它们是标在同一具模型表面上的节点，和肌肉出现在同一份点选名单里。有网格的用网格点选。只有落点的节点在模型上显示标记，在清单里同样可排序、派发和完成。

模型加载失败时，下半屏清单仍可派发、排序和完成。一项任务只记录选中的名字，不把模型文件写进当天的单。

整库两千多块网格、OpenSim 生物力学计算、摄像头动捕都不做。摄像头即使在手机本地算出关节点，得到的也是火柴人，给不出要松解的肌肉和方向。

## 数据

微信云开发存一份共享数据。

- 治疗室：口令、人名名单。每台微信记下自己点过的「我是谁」。
- 病人：姓名、若干病症。
- 病症：名称、要治的地方、有序的下手项。
- 下手项：肌肉或节点、手法、方向、剂量、顺序。
- 今日单：日期、当天的病人、从病症复制来的快照。快照另含派给谁、完成状态，以及今天实际使用的顺序。

把病人加入今天时，从病症复制快照。此后两边分开。后保存的顺序覆盖同一天的顺序。完成以先写入成功的那次为准。网络没有写成功时，按钮保持原状并提示未保存，不把未上云的操作显示成已完成。

## 以后再做

账号注册、按身份限制修改、整库解剖网格、OpenSim、摄像头动捕、点选膝盖就自动带出固定肌肉链、小程序注册主体的正式资质。主体未定不影响现在这些页面。

## 验收

1. 未输入过口令的微信要先输入口令，再点自己的名字，然后看到今日单。
2. 只有一条病症的老病人，点进后直接看到原有顺序和手法，点一次即可全部派给某人，并可逐项完成。此过程不用打开人体。
3. 新病症按点选先后出现在清单和人体上。离开后再次进入，这串还在该病症里。
4. 助手拖动顺序后，另一台微信重新进入该病人或下拉今日单，看到同一条顺序。
5. 只改派给谁或完成，病症里的原顺序不变。改了顺序并选择不更新，病症仍是旧顺序，今天的单是新顺序。
6. 一条病症可以复制到另一个病人，新病人的派给谁是空的，要重新填。
7. 模型加载失败时，仍能对清单派发、排序和点完成。
